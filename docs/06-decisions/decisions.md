## 아키텍처 결정

### D-001 View에서 DB 직접 호출 금지 (로컬 DB·보안 저장소에도 동일 적용 — D-234) ✅
- **결정**: app/ 하위 화면 파일에서 DB(로컬 SQLite)·SecureStore 직접 import 금지. 화면은 store만 호출하고, SQL은 `lib/`(localDb)와 store에서만 실행한다.
- **이유**: Controller 레이어를 거쳐야 낙관적 업데이트·에러 처리·캐싱을 일관되게 적용 가능
- **영향**: 모든 View 파일, store/, lib/
- **날짜**: 2026.08.30

### D-002 날짜 처리: KST(UTC+9) 고정 ✅
- **결정**: `new Date().toISOString().slice(0,10)` 사용 금지. 기기의 `getFullYear()/getMonth()/getDate()`(기기 타임존 의존)도 직접 쓰지 않고, `lib/date.ts`의 `localDateStr()`(UTC epoch에 9시간을 더해 KST로 고정 계산)만 사용한다.
- **이유**: UTC 기준이라 한국(KST, UTC+9) 날짜와 불일치 발생. 기기 타임존 설정에 의존하면 사용자가 해외에 있거나 기기 시간대가 KST가 아닐 때 날짜가 틀어진다. 날짜가 하루씩 밀리면 스트릭·알림 예약·일 단위 확정이 전부 어긋난다.
- **영향**: 날짜를 다루는 모든 파일 (`lib/date.ts` 등)
- **날짜**: 2026.08.30

### D-003 색상/간격 토큰 강제 ✅
- **결정**: 색상·간격 하드코딩 금지, `COLORS`/`SPACING`/`FONT`/`RADIUS` 토큰만 사용

## UI/UX 결정

### D-102 텍스트 입력 화면은 키보드 회피를 기본 적용한다 ✅

- **이유**: `adjustResize`만 믿고 넘어갔다가 폼 화면에서 키보드가 입력란을 가리는 문제가 실기기에서 재현됨.

### D-103 `Link asChild`(expo-router)에는 배열이 아닌 단일 스타일 객체를 전달한다 ✅

### D-212 상태바는 항상 어두운 아이콘, 상단 콘텐츠는 세이프에어리어 인셋 적용 ✅

## Time 탭 결정 (v2에서 일부 개정 — D-239, D-245, D-250)

### D-229 Time 탭(F-21) — 나의 시간 설정 + 하루 여러 건 시간 기록 ✅ (저장소는 D-234로 로컬 전환 📝)
- **결정**:
  1. 하단 탭 중 "Time" 탭(`(tabs)/time.tsx`)이 이 앱의 중심 화면이다.
  2. 설정 탭의 "나의 시간" 항목이 설정 팝업(`modal/time-settings`)을 연다. 날짜 선택은 `@react-native-community/datetimepicker`(mode="date")를 재사용하고 시간당 금액은 숫자 입력이다(기간별 다중 설정은 D-239).
  3. "오늘의 의미있는 일" 기록은 하루 여러 건 허용한다. Time 탭 "오늘 나의 시간" 라인 끝의 연필 아이콘 → `modal/time-log`(제목/내용/시간)에서 저장하면 새 기록이 **누적**되고(수정 아님), 그날의 합계가 "오늘 나의 시간"이다.
  4. 계산 기준: 오늘 나의 금액 = 오늘 나의 시간 × 단가, 오늘 버려진 금액 = 버려진 시간 × 단가, 남은 금액 = 남은 일수 × 하루 가용시간 × 단가. 완료일이 지났거나 시작일이 미래여도 계산값을 그대로 표시한다(v2에서는 마지막 기간이 지나면 "새 기간을 추가해주세요" — logic.md § 2).
  5. Time 탭의 라벨·숫자는 FND(7세그먼트) 스타일 폰트(오픈소스 **DSEG7-Classic**, SIL OFL)로 표기한다. `assets/fonts/`의 Regular/Bold TTF를 `expo-font`(`useFonts`)로 로드하고 `FONT.familyFND`로 노출한다. 이 폰트에 한글 글리프가 없어 한글은 시스템 폰트로 대체된다.
- **이유**: 시간/돈을 등가로 환산해 "오늘 얼마나 의미있게 썼는지"를 시각화하는 기능.
- **영향**: `app/(tabs)/time.tsx`, `app/modal/time-log.tsx`, `app/modal/time-settings.tsx`, `store/useTimeStore.ts`, `components/ui/icons.tsx`, `assets/fonts/*`, `constants/theme.ts`, `app/_layout.tsx`
- **날짜**: 2026.09.15

### D-230 Time 탭을 스크롤 없이 한 화면에 고정, 가용시간은 사용자 설정값 ✅ (구성은 D-245로 개정)
- **결정**: `app/(tabs)/time.tsx`는 `ScrollView`를 쓰지 않는다. 루트를 `flex:1`로 두고 블록을 `justifyContent: 'space-between'`으로 배치해 AppHeader 아래부터 하단 탭 바 바로 위까지 스크롤 없이 항상 다 보이게 한다. 하루 가용시간은 고정 상수가 아니라 사용자 설정값(1~24시간, 기본 8)이다.
- **이유**: 스크롤이 필요해 한눈에 안 보였고, 수면 시간 가정이 사람마다 다를 수 있음.
- **영향**: `app/(tabs)/time.tsx`, `app/modal/time-settings.tsx`, `constants/time.ts`
- **날짜**: 2026.09.16

### D-231 오늘 버려진 시간/금액을 실시간 계산, 시간 기록 삭제 ✅
- **결정**:
  1. "오늘 버려진 시간"은 활동 시간대(기본 06:00~22:00) 안에서 `availableHours × 경과 비율 − 오늘 나의 시간`(0~availableHours로 clamp)을 그때그때 다시 계산하는 **순수 함수**(`lib/timeTicker.ts`의 `computeLiveWastedHours()`)다. 활동 시작 전에는 0, 종료 이후에는 `availableHours − 오늘 나의 시간`으로 수렴·정지한다. 화면이 1초 타이머로 재호출한다(logic.md § 4). **오늘에 한한 값**이며 하루가 지나면 D-251의 확정 값으로 고정된다.
  2. `modal/time-log`의 저장 버튼은 상단 헤더(제목 옆, 닫기 ✕ 왼쪽)에 둔다. "최근 3일 기록" 각 항목 오른쪽의 휴지통 아이콘은 확인 Alert 후 삭제한다(**오늘 기록만 가능**, D-250).
- **이유**: "버려진 시간"이 하루 동안 흘러가는 감각을 실시간으로 보여 주고, 잘못 입력한 기록을 지울 수 있어야 함. 기록 시점마다 구간별로 속도를 다시 계산하는 방식은 기록이 겹치면 종료 시점 값이 어긋나는 버그가 있어 경과 비율 기반 순수 함수로 교체했다.
- **영향**: `lib/date.ts`(`kstMsSinceMidnight`/`hhmmToMs`), `lib/timeTicker.ts`, `app/(tabs)/time.tsx`, `app/modal/time-log.tsx`
- **날짜**: 2026.09.16

### D-223 릴리스 서명용 정식 키스토어 ✅ (v2에서 변경하지 않음)
- **결정**: `android/app/thinketh.keystore`(PKCS12, alias `thinketh`)로 `release`를 서명하고, 비밀번호/alias는 코드에 하드코딩하지 않고 `android/keystore.properties`에 둔다. `android/app/build.gradle`은 이 파일이 있으면 그 키로, 없으면 `debug` 키로 서명한다. 두 파일은 `.gitignore`(`*.keystore`, `keystore.properties`) 대상이라 **커밋하지 않는다.**
- **이유**: `release` 빌드타입이 디버그 키로 서명되고 있어 정식 키를 발급했다. v2 전환(D-250~D-254)에서도 서명 구성은 건드리지 않는다(개발자 결정 2026.10.14).
- **주의**: 두 파일은 git에 없으므로 프로젝트 밖(비밀번호 관리자 등)에 별도 백업한다. 분실하면 기존 설치본과 업데이트 호환이 끊기고, 서버·백업 없이는 앱을 지우고 재설치해야 해 **데이터가 사라진다**(D-236). 내보내기 백업(F-25)을 정기적으로 만든다.
- **영향**: `android/app/thinketh.keystore`, `android/keystore.properties`, `android/app/build.gradle`, `.gitignore`
- **날짜**: 2026.09.07

### D-234 서버 폐기 — 모든 기능을 휴대폰 안에서만 구현한다 📝
- **결정**: 서버·계정·네트워크 의존을 모두 없앤다. 데이터는 기기의 SQLite 하나(D-236 암호화)에 저장한다. D-001의 "View에서 DB 직접 호출 금지" 원칙은 로컬 DB에도 동일하게 적용한다 — 화면은 store만 호출하고, SQL은 `lib/`(localDb)와 store에서만 실행한다.
- **이유**: 개발자 결정 — 개인용 앱이라 클라우드 동기화가 불필요하고, 데이터를 타인·서버에 두고 싶지 않음.
- **영향**: `lib/supabase.ts`, `store/useAuthStore.ts`, `app/(auth)/*`, 의존성 정리, `useTimeStore`(전면 교체), 문서 전반
- **날짜**: 2026.10.14

### D-235 로그인은 "앱 잠금"으로 대체한다 (6자리 PIN 필수, 생체인증 선택) 📝
- **결정**: 이메일 로그인/회원가입(F-01)을 없애고 앱 잠금(F-23)으로 대체한다.
  1. 첫 실행 시 6자리 PIN 설정(필수). 생체인증은 선택.
  2. PIN은 **해시+솔트**만 `expo-secure-store`에 저장하고 평문은 저장하지 않는다. 연속 5회 실패하면 대기 시간을 늘린다.
  3. 백그라운드 진입 후 설정 시간(기본 30초, 설정에서 변경 가능)이 지나면 다시 잠근다. 최근 앱 목록 미리보기는 **잠금 중이거나 백그라운드일 때만** 가린다(`expo-screen-capture`로 `FLAG_SECURE` 적용). 평소 사용 중에는 스크린샷을 막지 않는다.
  4. PIN 분실 시 **기기 잠금(지문·화면 비밀번호) 인증으로 PIN 재설정**. 데이터는 지워지지 않는다. 기기에 화면 잠금이 없으면 재설정이 불가능함을 설정 화면에서 미리 알린다.
  5. DB 암호화 키는 PIN과 무관한 무작위 키다(D-236) — PIN을 바꿔도 DB를 다시 암호화하지 않는다.
- **이유**: 개발자 결정 — "로그인은 타인이 보지 못하게 하기 위한 설정 정도".
- **영향**: `app/lock.tsx`(신규), `store/useLockStore.ts`(신규), `lib/secure.ts`(신규), `app/_layout.tsx`, `settings.tsx`(프로필 카드·로그아웃 → 잠금 설정), `expo-local-authentication`, `expo-secure-store`, `expo-screen-capture`
- **날짜**: 2026.10.14

### D-236 로컬 DB는 SQLCipher로 암호화하고, 키는 SecureStore에 보관한다. 자동 백업은 끈다 📝
- **결정**: `expo-sqlite`의 SQLCipher 옵션(`useSQLCipher`)으로 DB 파일 전체를 암호화한다. 키는 첫 실행 때 생성한 무작위 256비트 값을 `expo-secure-store`(Android Keystore)에 저장하고, SQLCipher에는 문자열 암호가 아니라 **raw 키 형식**(`PRAGMA key = "x'<hex>'"`)으로 직접 지정한다(키 유도 반복을 건너뛰어 앱 시작이 느려지지 않게 함). `AndroidManifest`의 `allowBackup`을 `false`로 하고 자동 백업 대상에서 제외한다 — 키가 기기에 묶여 있어 백업본을 복원해도 열 수 없으므로, 백업은 D-237의 내보내기/가져오기만 사용한다. 스키마 변경은 `schema_version` 테이블 기반의 순차 마이그레이션으로 관리하며, **앱이 아는 것보다 새로운 `schema_version`의 DB는 열지 않고** "앱을 업데이트해 주세요"를 안내한다(다운그레이드로 인한 손상 방지). DB를 열 수 없을 때의 흐름은 D-253.
- **이유**: 회고·금액 등 민감 정보를 평문으로 두지 않기 위해(개발자 확인). 앱 데이터 삭제나 재설치 시 키가 사라져 **복구 불가**하다는 점을 설정 화면과 문서에 명시한다.
- **영향**: `lib/localDb.ts`(신규), `app.json` 플러그인, `AndroidManifest.xml`, 개발용 빌드 필요(Expo Go 불가)
- **날짜**: 2026.10.14

### D-237 백업은 내보내기/가져오기, 비밀번호 암호화 필수 📝

### D-239 시간당 비용은 "기간별 다중 설정"이며 기간 사이에 빈 날이 없어야 한다 📝 (과거 수정 규칙은 D-250이 대체)

  1. 시작일·종료일·시간당 금액을 한 쌍이 아니라 **여러 기간**(`rate_periods`)으로 등록한다. 예: 2026.10.01~2026.12.30 5만 원, 2027.01.01~ 10만 원.

### D-242 동기 강화 기능(F-26~F-31)의 계산 규칙 📝
- **스트릭**: 그날 나의 시간 합계 ≥ 스트릭 기준(기본 1시간, 설정 변경 가능)이면 달성. 오늘은 하루가 끝나기 전에는 스트릭을 끊지 않는다. 일일 목표(예: 2시간)는 스트릭 기준과 별개이며 진행 막대에만 쓴다. 기준 변경은 다음 날부터 적용된다(D-250).
- **프리즈**: 주 1회(월~일, KST). 별도 저장 없이 **기록에서 매번 계산**한다 — 빠진 날이 있고 그 주에 프리즈가 남아 있으면 해당 날을 자동으로 이어 준다. 지난 날은 수정할 수 없으므로(D-250) 이미 지난 주의 프리즈 사용은 사실상 확정이며, 오늘 빠진 기록을 채우면 프리즈 사용은 자동으로 취소된다(저장 테이블 없음).
- **타이머**: 시작 시각을 DB에 저장하고 `now − started_at`으로 계산해 앱을 껐다 켜도 이어진다. 자정을 넘기면 날짜별로 나눠 기록하고, 최대 12시간을 넘으면 정지 시 확인을 받는다. 0.01시간(36초) 미만은 올림한다. 타이머 시간은 나의 시간으로 간주하므로 타이머 중에는 버려진 금액이 늘지 않는다. 기기 시계를 되돌려 경과가 음수가 되면 0으로 고정하고, 정지 시각이 시작 시각보다 이전이면 저장을 거부한다.
- **복리 환산**: 이번 달 나의 금액을 매월 납입으로 보고 12개월 미래가치를 계산한다. 가정 수익률은 설정에서 바꿀 수 있고 기본값은 연 5%다. 화면에 "가정 시뮬레이션"임을 항상 표기한다.
- **태그**: `tags` 테이블, 기록(`time_logs.tag_id`)에 연결. 삭제된 태그의 기록은 "미분류"로 둔다.
- **마일스톤**: 누적 나의 금액이 100만/300만/500만/1,000만/3,000만/1억 원을 처음 넘으면 `achieved_at`을 기록하고 축하 화면을 보여 준다. **받은 배지는 영구 유지**. 보상 문구는 사용자가 단계별로 직접 입력한다.
- **회고**: 하루 1건(`reflections`), 알림이나 통계 탭에서 작성. 오늘 것만 수정 가능(D-250).
- **영향**: `lib/streak.ts`, `lib/compound.ts`, `useTimerStore`, `useTagStore`, `useRewardStore`, `useReflectionStore`(모두 신규)

### D-250 지난 날짜의 기록·설정은 수정할 수 없다 (당일만 수정 가능) 📝 (D-239의 "과거 재계산 후 확인" 규칙을 대체)
- **결정**: 기준은 오늘(KST, D-002)이고 **어제까지가 과거**다. 과거는 재계산되지 않는다.
  1. **시간 기록·회고**: 날짜가 오늘인 것만 추가·수정·삭제할 수 있다. 자정이 지나면 즉시 수정 불가이며, 판정은 날짜 비교로 하므로 일 단위 확정(D-251)이 늦어져도 영향이 없다.
  2. **시간당 비용 기간**: 시작일이 오늘보다 이전인 기간(=과거 날짜를 포함한 기간)은 단가·시작일을 바꿀 수 없고 삭제할 수 없다. 종료일은 오늘 이후 날짜로만 바꿀 수 있다. 새 단가가 필요하면 현재 기간의 종료일을 오늘로 끊고 내일부터 시작하는 새 기간을 추가한다. 시작일이 오늘 이후인 기간은 자유롭게 수정·삭제할 수 있다(D-239의 겹침·빈 날 검증은 그대로).
  3. **하루 가용시간·활동 시간대·일일 목표·스트릭 기준**: 변경은 **다음 날부터** 적용된다. 날짜별 적용값은 `day_settings`(적용 시작일 포함)로 저장하며, 오늘 이전의 행은 수정할 수 없다. 내일 시작 행은 자정 전까지 몇 번이든 고칠 수 있다.
  4. 과거가 고정되므로 누적 나의 금액은 줄어들지 않고, 마일스톤 "영구 배지"(D-242)와 충돌하지 않는다.
  5. 화면은 과거 항목을 읽기 전용으로 보여 주고, 수정이 불가능한 이유를 안내한다("이미 확정된 기록입니다").
- **이유**: 개발자 결정(2026.10.14) — "지나간 일자와 시간에 대해서는 재계산하지 못하도록 해야 함", "기록한 내용은 다음날 확정 후에는 수정불가".
- **영향**: `lib/rates.ts`(수정 가능 여부 판정), `store/useTimeStore.ts`·`useRateStore.ts`·`useReflectionStore.ts`, `app/modal/time-log.tsx`·`time-settings.tsx`, db-schema(`day_settings`), logic.md, ux-patterns.md
- **날짜**: 2026.10.14

### D-251 하루가 지나면 그날을 "확정(스냅샷)"한다 — 앱을 열 때 실행 📝
- **결정**: 오늘 이전의 날짜 중 확정 행이 없는 날을 `day_closings`에 저장한다(그날의 나의 시간, 가용시간, 단가, 버려진 시간·금액, 나의 금액). 실행 시점은 ① 앱 시작 ② 백그라운드에서 포그라운드 복귀 ③ 앱이 켜진 채 자정을 넘길 때(매초 `today` 비교 로직 연결)이며, 여러 날이 밀려 있으면 오래된 날부터 한 번에 일괄 확정한다. **정시(0시 5분) 백그라운드 실행은 쓰지 않는다**(정시 보장 불가 — D-241, 정밀 알람 권한 미사용). 수정 가능 여부는 날짜로 판정하므로(D-250) 확정이 늦어져도 정합성이 깨지지 않는다. 확정 값은 그날 적용값(`day_settings`, `rate_periods`)으로 결정적으로 계산되므로 나중에 실행해도 같은 결과가 나온다.
- **이유**: 설정·단가가 나중에 바뀌어도 과거의 "버려진 금액" 등이 변하지 않게 하고, 누적 현황을 빠르게 읽기 위해.
- **영향**: `lib/closing.ts`(순수 함수), `useTimeStore.closePastDays()`, `app/_layout.tsx`(시작 순서), db-schema(`day_closings`), logic.md
- **날짜**: 2026.10.14

### D-252 기록 저장 뒤의 후속 처리는 저장과 분리해 격리한다 📝
- **결정**: 기록 저장·수정·삭제는 DB 트랜잭션 하나(기록 반영 + 해당 날짜 데이터)로 끝내고, 성공하면 그 시점에 사용자에게 성공을 알린다. 이후 스트릭 재계산·마일스톤 검사·알림 재예약·위젯 갱신은 **서로 독립적인 최선 노력(best-effort)** 으로 실행한다. 하나가 실패해도 다른 처리와 기록 저장 결과에 영향이 없고, 오류만 기록한다(레코드 내용·금액은 로그에 넣지 않는다 — D-244). 실패한 후속 처리는 **앱 시작 점검**에서 다시 실행한다(마일스톤 재검사, 알림 7일 재예약). 마일스톤은 `achieved_at`을 저장한 뒤에만 축하 화면을 띄워 같은 배지가 두 번 뜨지 않게 한다. 스트릭은 저장하지 않고 기록에서 매번 계산하므로 실패할 일이 없다.
- **이유**: 부수 효과 하나의 오류 때문에 이미 저장된 기록이 "실패"로 보이는 것을 막기 위해.
- **영향**: `store/useTimeStore.ts`, `useTimerStore.ts`, `lib/notifications.ts`, `lib/widgetBridge.ts`, `useRewardStore`
- **날짜**: 2026.10.14

### D-253 네이티브 변경은 git으로 추적하고, 백업 병합 규칙과 DB 열기 실패 흐름을 정한다 📝
- **결정**:
  1. **네이티브 버전 관리**: `android/`를 git으로 추적한다(`.gitignore`에서 `/android` 전체 제외를 풀고 `build/`, `.gradle/`, `.cxx/`, `local.properties`, `*.apk`, `*.aab`, `*.keystore`, `keystore.properties`만 제외). 위젯 Kotlin·매니페스트 수정은 설정 플러그인으로 코드화하지 않고 `android/`의 직접 수정으로 둔다. `prebuild --clean`은 쓰지 않으며, 쓰더라도 git diff로 복구한다.
  2. **백업 가져오기 병합**(덮어쓰기 모드는 확인 후 전체 교체): `rate_periods`와 `day_settings`는 항상 통째 교체(병합 시 겹침·빈 날·확정 값 불일치 방지). 그 외 테이블은 id(또는 date) 기준으로 병합하고 `updated_at`이 최신인 쪽을 채택한다. **이미 확정된 날짜(`day_closings`가 있거나 오늘 이전)의 로컬 기록·회고는 병합으로 덮어쓰지 않는다**(D-250). 가져온 뒤 일 단위 확정, 알림 재예약, 위젯 갱신, 마일스톤 검사를 실행한다.
  3. **DB 열기 실패 흐름**: 시작 중에는 스플래시를 유지하고 PIN 확인 **뒤에** 안내 화면을 보여 준다. 어떤 경우에도 자동 삭제하지 않는다.
     - 새 버전 DB(`schema_version`이 앱보다 높음): "앱을 업데이트해 주세요", 닫기만 가능
     - 키 분실·불일치/파일 손상: ① 백업 파일에서 가져오기 ② 새로 시작(직접 "삭제"를 입력해야 진행). 두 경우 모두 기존 DB 파일은 지우지 않고 `thinketh.db.bak-날짜`로 이름만 바꿔 보존한다
     - 일시적 오류: 재시도(몇 회 후 위 화면)
- **이유**: 개발자 결정(2026.10.14) — git으로 네이티브 변경을 보존, 병합 안전성, 데이터 유실 방지.
- **영향**: `.gitignore`, `lib/backup.ts`, `lib/localDb.ts`, `app/_layout.tsx`, DB 열기 실패 화면(신규), setup-build.md
- **날짜**: 2026.10.14
